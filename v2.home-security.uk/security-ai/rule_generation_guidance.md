# Security Rule Generation Guidance for Ollama LLM

This document provides guidance for generating production-ready Suricata detection rules and firewall-cmd blocking rules from security event analysis.

## Overview

The security-ai worker now generates two types of rules:

1. **Suricata IDS Rules** - Network-based intrusion detection patterns
2. **Firewall-cmd Rules** - IP blocking and service management rules

Both are generated by the LLM based on analyzed security events, with strict validation before deployment.

## Suricata Rule Generation

### Rule Structure

All AI-generated Suricata rules must follow this format:

```
alert <protocol> <source_ip> <source_port> -> <dest_ip> <dest_port> (
    msg:"<descriptive message>";
    <detection_options>;
    classtype:<classification>;
    sid:<1000000-1999999>;
    rev:1;
    metadata:
        created_at <YYYY-MM-DD>,
        cve <CVE-ID>,
        attack_type <attack_type>,
        source_id AI-GENERATED
)
```

### Supported Protocols

- `tcp` - TCP traffic
- `udp` - UDP traffic
- `http` - HTTP traffic (application layer)
- `icmp` - ICMP (ping/network diagnostics)

### Common Attack Patterns

#### 1. SSH Brute Force Detection

**Pattern:** Multiple SSH connection attempts from same source

```
alert tcp \$EXTERNAL_NET any -> \$HOME_NET 22 (
    msg:"AI-REC: SSH brute force attempt";
    flow:to_server,established;
    content:"SSH-";
    detection_filter:track by_src, count 5, seconds 60;
    classtype:attempted-admin;
    sid:1000001;
    rev:1;
    metadata:
        created_at 2026-01-01,
        cve CVE-2024-6387,
        attack_type brute_force,
        source_id AI-GENERATED
)
```

**Rationale:** Detect 5+ SSH attempts in 60 seconds from single source

#### 2. Port Scanning Detection

**Pattern:** Connection attempts to many ports in short time

```
alert tcp \$EXTERNAL_NET any -> \$HOME_NET [22,80,443,445,3306,27017] (
    msg:"AI-REC: Network reconnaissance - port scan detected";
    flags:S,12;
    flow:to_server,no_stream;
    detection_filter:track by_src, count 10, seconds 30;
    classtype:network-scan;
    sid:1000002;
    rev:1;
    metadata:
        created_at 2026-01-01,
        attack_type port_scan,
        source_id AI-GENERATED
)
```

**Rationale:** Alert when single source attempts 10+ port connections in 30 seconds

#### 3. DNS Tunneling Attempt

**Pattern:** Excessive DNS queries with unusual patterns

```
alert dns \$HOME_NET any -> \$EXTERNAL_NET 53 (
    msg:"AI-REC: Suspicious DNS activity - possible tunneling";
    flow:to_server;
    detection_filter:track by_src, count 100, seconds 60;
    classtype:protocol-command-decode;
    sid:1000003;
    rev:1;
    metadata:
        created_at 2026-01-01,
        attack_type c2_beacon,
        source_id AI-GENERATED
)
```

**Rationale:** Excessive DNS queries may indicate C2 communication or data exfiltration

#### 4. HTTP DoS Detection

**Pattern:** Rapid HTTP requests from single source

```
alert http \$EXTERNAL_NET any -> \$HOME_NET any (
    msg:"AI-REC: HTTP flood - potential DoS attack";
    flow:to_server,established;
    detection_filter:track by_src, count 50, seconds 10;
    classtype:abuse-of-service;
    sid:1000004;
    rev:1;
    metadata:
        created_at 2026-01-01,
        attack_type dos,
        source_id AI-GENERATED
)
```

**Rationale:** Alert on 50+ HTTP requests in 10 seconds from single source
